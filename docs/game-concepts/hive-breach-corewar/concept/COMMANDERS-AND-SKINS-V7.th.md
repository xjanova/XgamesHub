# COREWAR V7 — Humanoid Alien Commanders & Skins
วันที่ 7 ตุลาคม 2026 · สเปกออกแบบและภาพคอนเซปต์สำหรับพัฒนาต่อ · ยังไม่ได้สร้างระบบร้านค้า/คลังสกิน/RTS ในเกมจริง

## 1. ข้อกำหนดที่เจ้าของเพิ่ม
คอมมานเดอร์ฝั่งเอเลี่ยนต้องเท่ มีรูปร่างและใบหน้าคล้ายคน แต่เป็นเอเลี่ยนจริง และมีระบบสกิน ทั้งสองเผ่ามีตัวเลือกชาย/หญิงตามกติกาเดิม บัญชีเดียวเล่นได้ทุกฝ่าย

คง V6 แมพสุ่ม/การสำรวจ/Fog และ V5 บัญชี/PvE/อาชีพ/ยศ/ซีซั่น พร้อมสกิลเฉพาะตัวและพาสซีฟของ V4 การเพิ่มหน้าตาคอมมานเดอร์ไม่เปลี่ยนฝ่าย RTS ให้เป็นเกมเดินฮีโร่

ทุกแบบมีแขนสองข้าง ขาสองข้าง ใบหน้าอ่านอารมณ์ได้ และลักษณะต่างดาวชัดจากผิว ดวงตา หู และวัสดุบนศีรษะ MYRAX ใช้เส้นโค้งที่ดูมีชีวิต AETHERION ใช้เหลี่ยมผลึกและเครือข่ายแสง ไม่ออกแบบทุกคนให้เป็นมนุษย์ใส่หมวกหรือเป็นแมลงทั้งหน้า

KHAEL กับ SAERYN ใช้ MYRAX RaceID เดียวกัน VAEL กับ NYXARA ใช้ AETHERION RaceID เดียวกัน การเลือกชาย/หญิง/บุคลิกเป็น AppearanceID ไม่เพิ่ม stats หรือเปลี่ยนยูนิตราคา ความสามารถและ Doctrine ใช้จากเผ่า/อาชีพที่บัญชีปลดล็อกตาม V5

## 3. คอมมานเดอร์ปรากฏที่ไหน
- หน้าเลือกเผ่า/ตัวละคร: ดูตัวเต็ม หมุนดูเครื่องแต่งกาย ทดลองสกิน และเลือกเสียง/ท่าทาง
- RTS: พอร์ตเทรตผู้บัญชาการที่มุมจอ ตอบรับคำสั่ง เตือนฐาน และแสดงท่าพิเศษหลังภารกิจ
- PvE เอเลี่ยนและคัตซีน: ตัวแทนผู้เล่นที่ฐานบัญชาการ เล่าเรื่องและสั่งกองทัพ
- หลังจบแมตช์: แสดงยศ ผลงาน และสกินที่สวม

ต้นแบบ RTS ไม่ต้องมีตัวคอมมานเดอร์เดินสู้ในสนาม ไม่มี HP ฮิตบ็อกซ์หรือการโจมตีใหม่จากตัวอวาตาร์ ถ้าภายหลังวางรูปคอมมานเดอร์ในฐาน ให้เป็น presentation ที่ไม่เปลี่ยนทางเดิน/การสร้างฐาน ช็อตภาพยนตร์ที่ยืนบัญชาการเป็นการเล่าเรื่อง ไม่ใช่ยูนิตต่อสู้ที่เพิ่มเข้า ruleset

## 4. ประเภทสกิน
| ช่อง | เปลี่ยนอะไร | ส่วนที่รักษาไว้ |
|---|---|---|
| Guardian Outfit | ชุด เกราะ ผม/เครื่องประดับ ผ้า | HeroID รูปทรงบทบาท animation timing และ hitbox |
| Commander Outfit | เกราะ คราวน์ ผ้าคลุม portrait/ท่าตอบรับ | RaceID, AppearanceID และ Doctrine |
| Weapon Skin | ผิวและรายละเอียดปืนพก ค้อน โล่ ดาบ | ประเภทอาวุธ จุดยิง ระยะจริง ความเร็ว และช่วงโจมตี |
| Unit Skin | กระดอง/แผ่นเกราะ/พื้นผิวของยูนิต RTS | UnitID ขนาดเท้า เงาร่างอ่านง่าย team tint และบทบาท |
| Building Skin | ผิว ปลอกอาคาร รายละเอียดเผ่า | footprint ทางผ่าน ระยะป้อม และขั้นตอนสร้าง |
| Core / Pet / Banner | เปลือกแกน สัตว์เลี้ยงตกแต่ง ธง กรอบโปรไฟล์ | CoreHP/ความสามารถ/การมองเห็นตาม ruleset |
| Cosmetic VFX / Voice | รายละเอียดแสง เสียงตอบรับ ท่าชนะ | telegraph สีแจ้งอันตราย timing และกฎ Fog |

สกินเปลี่ยนรูปลักษณ์อย่างเดียวใน PvE และ VS ไม่ให้ damage, defense, heal, lifesteal, vision, production speed, resource discount หรือโบนัส XP เพิ่ม ระบบซื้อแบตเตอรี่ PvE ตาม V5 เป็นระบบแยก ไม่รวมโบนัสไว้ในสกิน

ระดับ Common / Rare / Epic / Legendary แสดงความซับซ้อนของงานภาพและเสียง ไม่มี tier พลัง ชุดที่ปลดล็อกแล้วอยู่ในคลังถาวรหลังเปลี่ยนซีซั่น

## 6. หน้าจอเลือกสกิน
เลือกฝ่าย → เลือก HeroID หรือ AlienRaceID → เลือก AppearanceID → เปิด Skin Collection → Preview → Equip

ซ้าย: เผ่าและพอร์ตเทรตตัวละคร กลาง: ตัวเต็มและฉากแสดงชุด ขวา: สกินสถานะ Owned / Selected / Preview พร้อมแหล่งรับ ด้านล่าง: Equip Skin / Preview และข้อความ Appearance Only

Preview ใช้ได้ก่อนรับสกิน แสดงชุดได้ในหน้าทดลองโดยไม่บันทึกลง loadout ก่อนมีสิทธิ์ เมื่อกดรับจากร้านค้าให้สรุปชุดและสิทธิ์ที่ได้รับชัดเจน; ราคาและช่องทางชำระเงินจริงยังไม่กำหนดในสเปกนี้ ไม่ใช้กล่องสุ่มเป็นเงื่อนไขหลักในการรับสกิน

เชื่อมรางวัลกับระบบเดิม: รางวัลฟรีจากเนื้อเรื่อง/ภารกิจ/ความชำนาญ/ซีซั่น และร้านค้าหรือ premium cosmetic track ไม่มีการซื้อข้ามบททดสอบยศหรือได้อาชีพจากการซื้อสกิน

## 7. ความชัดเจนในสนาม
- สีทีม outline วงเลือก target ring พื้นที่สกิล และเครื่องหมาย telegraph อยู่เหนือวัสดุสกิน
- ปืนพกยังอ่านเป็นปืนพก ค้อนยังมีขนาดภาพและระยะรับรู้เหมาะกับ hitbox เดิม; โล่ไม่ขยายจริงจากชุด Legendary
- unit silhouette แยก Skitter / Brute / Sentinel ได้ใน RTS ระยะไกล ป้อมกับอาคารผลิตไม่สลับรูปทรงจนอ่านผิด
- ผิวสกินไม่ทำให้ตัวละครโปร่งหาย ไม่มีแสงปิดทับเป้าหมายหรือสีหลอก team alignment; เอฟเฟกต์ที่เปลี่ยนสีภัยคุกคามไม่ผ่าน validation
- เสียง/แสงจากสกินมาจาก entity ที่ผู้เล่นมีสิทธิ์รับรู้ตาม Fog เท่านั้น ไม่ส่ง VFX/เสียงคำสั่งระบุตำแหน่งฐานที่ยังไม่พบ
- ให้ตั้งโหมด Competitive Clarity เพื่อใช้รูปลักษณ์มาตรฐานของศัตรูพร้อมสีทีมได้ โดยสกินตนเองยังแสดงใน UI/คัตซีน
- ล็อก cosmetic loadout ตอนเริ่มแมตช์ เพื่อไม่เกิดการโหลด/เปลี่ยนรูปลักษณ์ขณะต่อสู้

## 8. โครงสร้างข้อมูลและการพัฒนาจริง
แยกข้อมูล GameplayLoadout (HeroID/RaceID, career, active, passive, research plan) ออกจาก CosmeticLoadout (AppearanceID, skin family, weapon skin, unit/building overrides, portrait, voice, banner) โค้ดคำนวณต่อสู้ไม่อ่าน cosmetic multiplier เพราะฟิลด์นั้นไม่อยู่ใน schema

คลังสิทธิ์อยู่ระดับบัญชี เซิร์ฟเวอร์ตรวจ owned + compatibility ก่อน equip การให้รางวัล/ซื้อใช้ transaction ID เดิมแล้วให้สิทธิ์เพียงครั้งเดียว ถ้าสกิน/เวอร์ชันหาย fallback เป็นชุดมาตรฐานโดยไม่เปลี่ยนสกิล ไม่ให้ client อ้าง SKU หรือไฟล์รูปเพื่อได้สิทธิ์เอง

ข้อมูลตัวอย่างใน skin-system-data.json เป็น catalog สำหรับต่อ implementation ไม่ได้เชื่อมเงินจริงและยังไม่มี entitlement service ข้อมูล visual field ต้องผ่าน validator ว่า target/type/faction/appearance เข้ากัน

เพื่อลดงาน 2.5D เริ่มจากเปลี่ยนวัสดุ/สี/ชิ้นเครื่องประดับบนโครงกระดูกและ animation เดิม ใช้คลิป portrait/menu สำหรับคอมมานเดอร์ก่อน แทนการเพิ่มชุดท่าเดินโจมตีครบทุกทิศของตัวใหม่ ยูนิต/อาคารใช้ชุดภาพที่ render/bake จาก asset เดิมแต่ต้องตรวจตามกล้อง RTS จริง พรีโหลด atlas ของแมตช์และกำหนดงบ VFX ร่วมกัน

ลำดับต้นแบบ:
1. เลือก Commander Appearance ชาย/หญิงสำหรับสองเผ่า พร้อม portrait และ base skin
2. Skin preview/equip แบบ local catalog และ save loadout
3. เชื่อมคลังบัญชี/ภารกิจซีซั่น ทดสอบการคืนโหลดและ compatibility
4. เปรียบเทียบสกินกับรูปมาตรฐานในกล้อง RTS/ฮีโร่และ Fog
5. เพิ่ม unit/building skin หลังงบภาพและความอ่านง่ายผ่าน
6. เชื่อมร้านค้าเมื่อมีระบบสิทธิ์/ธุรกรรมที่ตรวจสอบได้แล้ว

## 9. ชุดภาพโปรโมทล่าสุด
