# HIVE // BREACH: COREWAR — V6 สนามสุ่มที่ต้องสำรวจ
วันที่ 7 ตุลาคม 2026 · ส่วนเพิ่มจาก V5 · สเปกระบบเกมและตัวอย่างตรรกะ

## 1. ข้อกำหนดของเจ้าของ
ทุกแมตช์ในโหมดแมพสร้างสนามใหม่ ผู้เล่นไม่รู้ผังล่วงหน้า จึงต้องสำรวจและปรับแผนจากข้อมูลที่พบ ทั้งผู้ปกป้องและคอมมานเดอร์เอเลี่ยน
สุ่มโครงสร้างจริง: เส้นทาง ทางแยก วงรอบ ช่องบุก จุดทรัพยากร จุดสำรวจ เสบียง สภาพพื้นที่ และตำแหน่งเป้าหมาย ไม่ใช่เปลี่ยนสีฉากเดิม
ผู้เล่นยังเรียนรู้วิธีอ่านภูมิประเทศและรูปแบบยูนิตได้ แต่พิกัดฐาน ทรัพยากรและเส้นทางของรอบก่อนเอามาใช้ตรง ๆ ในรอบใหม่ไม่ได้
ไม่กล่าวอ้างว่าไม่มีทางเกิดแมพคล้ายกันตลอดไป ระบบใช้โครงสร้างหลายแบบและตรวจความซ้ำล่าสุด เพื่อลดการเจอสนามเดิมหรือสนามที่เปลี่ยนเพียงภาพตกแต่ง
หนึ่งแมตช์มีโลกเดียว ผู้เล่นสองฝั่งใช้ terrain, collision, navigation และ objectives ชุดเดียว ต่างกันที่กล้องและข้อมูล vision
V6 แทนการใช้ผัง Frost Relay/Ash Garden/Orbital Rain แบบตายตัว: ชื่อเดิมกลายเป็นธีมและชุดชิ้นส่วน ฉากและระบบ Hero/PvE/ยศ/ร้านค้า V4–V5 ใช้ต่อ

## 2. สิ่งที่สุ่มในแต่ละสนาม
| ชั้น | สิ่งที่เปลี่ยน | สิ่งที่ตรวจ |
|---|---|---|
| โครงสร้างยุทธศาสตร์ | รูปแบบวงรอบ จำนวนทางแยก ทางอ้อม พื้นที่คุมกลาง | ฐานถึงเป้าหมายได้ ไม่มีคอขวดเดียวที่ปิดทั้งเกม |
| พื้นที่และเส้นทาง | ลานโล่ง ซอกหุบเขา สะพาน ซากสถานี แนวกำบัง | ความกว้างยูนิต ฮีโร่และรถล้อมไม่ติด |
| ฐานและแกนดาว | ตำแหน่ง ระยะเดิน แนวบุก พื้นที่วางป้อม | พื้นที่สร้างฐานพอ ระยะบุกเริ่มต้นอยู่ในช่วง |
| เศรษฐกิจ | ตำแหน่ง resource clusters เสบียง จุดขยาย | งบเริ่มต้นและต้นทุนเดินเก็บเทียบเคียงกัน |
| การสำรวจ | relay จุดสังเกต ห้องลับและเส้นทางสำรอง | มองเห็นตาม LOS ไม่รู้พิกัดจาก HUD ก่อนพบ |
| PvE | เป้าหมายย่อย การวางศัตรู encounter และ arena | ภารกิจทำสำเร็จได้ ความยากและรางวัลตามระดับ |
| บรรยากาศ | สภาพอากาศ แสง ฝุ่น เศษฉาก ผิวพื้น | อ่าน hitbox/วงเตือนได้ ไม่ทำให้ฝ่ายหนึ่งเสียเปรียบ |

งบพลังอาชีพ สกิล กติกา VS ราคาในร้านค้า และสิทธิ์ PvE ต่อวันยังใช้ V5 ไม่เปลี่ยนตาม map seed
พื้นฐานเนื้อเรื่องและเป้าหมายใหญ่ยังอ่านรู้เรื่อง เช่นช่วยขบวนหรือป้องกันแกน แต่สถานที่และทางแก้ภายในสนามเปลี่ยน

## 3. การสร้างสนามอย่างมีเหตุผล
1. เลือก Ruleset, PvE mission family หรือ VS และธีมที่เข้ากับ tier
2. เซิร์ฟเวอร์สร้าง seed ลับจากแหล่งสุ่มที่เหมาะสม ผูกกับ MatchID และ generator version
3. สร้างกราฟโซน: ฐาน แกน เขตทรัพยากร เขตต่อสู้ เขตสอดแนม และทางอ้อม
4. ประกอบห้อง/พื้น/สะพาน/ทางเดินจากชุดชิ้นส่วน 2.5D ตาม socket และ clearance
5. วาง objectives และ resources ตามงบ/ระยะเวลาเข้าถึง ไม่วางอิสระจนบังทางสำคัญ
6. เลือก encounters, cover, hazards และสิ่งตกแต่งจาก tag ของแต่ละโซน
7. ตรวจกฎบังคับก่อน จากนั้นจัดอันดับคุณภาพและความต่างจากสนามล่าสุด
8. ถ้าไม่ผ่าน ให้ซ่อมจุดที่ผิดหรือสุ่ม candidate ใหม่ในเวลาจำกัด
9. ยืนยันผังก่อน ready/เริ่ม combat; บันทึก layout ที่สร้างเสร็จ แล้วเปิดโลกตาม vision

ความฉลาดช่วงแรกมาจากข้อจำกัด กราฟ และการประเมินที่ออกแบบดี ไม่จำเป็นต้องเรียกโมเดลภาษาให้แต่งแต่ละช่อง
เมื่อมีข้อมูลเล่นจริง จึงเพิ่มโมเดลประเมินความสนุก/ความสมดุลเป็นตัวช่วยจัดอันดับ โดยกฎความถูกต้องยังเป็น hard constraints
คัด candidate ด้วย quality score ได้ แต่ไม่ใช้คะแนนที่ตั้งเองเป็นหลักฐานว่าแมพสนุกแล้ว ต้องทำ blind playtest และวัดผลแยกสองฝั่ง

## 4. กฎตรวจ VS ก่อนใช้สนาม
- แกน ฐาน และ objectives เชื่อมกันจริงบน nav ของทุก unit class ที่อนุญาต
- เป้าหมายต้นแบบมีแนวบุกหลักอย่างน้อยสามแนวในระดับโซน และมีทางอ้อม ตรวจ edge/vertex cuts ไม่ให้นับทางเดินขนานในช่องแคบเดียวเป็นสามแนวอิสระ
- พื้นที่ฐานและ core defense มี footprint พอสำหรับอาคารที่จำเป็น และมีทางให้ worker ออก
- ความกว้างทางเดินตรวจจาก siege radius/formation ไม่ใช้เพียง BFS ของจุดขนาดหนึ่งช่อง
- เวลาเดินถึงทรัพยากรเริ่มต้นและปริมาณรวมอยู่ในช่วงใกล้เคียงกันตามกติกา 4v1 แต่พื้นที่ไม่จำเป็นต้องสะท้อนกระจก
- คุม shortest attack time, expansion time, core perimeter exposure และพื้นที่ที่ยิงถึงแกนจากระยะไกล
- ลานปะทะมีพื้นที่หลบ ไม่เกิดการเริ่มแมตช์แล้วป้อมยิงอีกฐานได้ทันที
- วงจรทำภารกิจไม่มี dependency ที่เป็นไปไม่ได้ เช่นกุญแจอยู่หลังประตูที่ต้องใช้กุญแจนั้น
- จุดสำรวจไม่เปิดโลกทั้งใบฟรี และไม่บังคับชนคอขวดที่ไม่มีทาง counter

ค่าต้นแบบของเกมจริงต้องเทียบ “เวลา/พื้นที่/ความสามารถยูนิต” ไม่แปลงจำนวนช่องในตัวอย่างเป็นค่า balance จริงทันที
ผล spawn distance เท่ากันไม่ได้พิสูจน์ว่า Guardian กับ Commander มีโอกาสชนะ 50% ต้อง simulation และ playtest ด้วยฝ่าย/บิลด์/เผ่าหลายชุด
เมื่อสุ่มไม่ผ่านในเวลาจำกัด ใช้ generator ความซับซ้อนต่ำที่ผ่านการตรวจและ seed ใหม่ ไม่ส่งสนามเสียและไม่ใช้ fallback แมพเดิมที่ทุกคนท่องได้
ถ้า fallback ยังไม่ผ่าน ให้ยกเลิกการจัดสนามและคืนสิทธิ์/ทรัพยากรที่ reserve อย่าง idempotent ก่อนผู้เล่นเสียประตู PvE

## 5. ป้องกันการจำผังล่วงหน้า
เก็บ fingerprint ของ topology, adjacency, path lengths, objective/resource distribution และ normalize การหมุน/สะท้อน เพื่อไม่ถือว่าแค่กลับแมพเป็นสนามใหม่เชิงกลยุทธ์
ใช้ประวัติสนามล่าสุดของ squad/account เช่น 20 แมตช์ และ recent global fingerprints ตามพื้นที่บริการเป็น soft constraints
ปรับ novelty threshold เมื่อ population/ธีมเล็ก แต่ไม่ลดกฎ connectivity/fairness และไม่อ้างว่าหลีกเลี่ยงความคล้ายได้ไม่จำกัด
สุ่มการเชื่อมโซนและตำแหน่งจุดสำคัญก่อนตกแต่ง เพื่อให้มีความต่างจริงแม้ใช้โมเดลชุดเดิม
งบ encounter/objectives คงอยู่ในช่วงความยากของยศ ทั้งวันเก็บ battery ไม่ทำให้ระบบสุ่มแมพง่ายขึ้นลับ ๆ
ไม่มีรายการผังทั้งหมดให้เลือกก่อนเข้า ผู้เล่นเลือกธีม/ภารกิจ/ระดับตามสิทธิ์ ส่วนผังจริงสร้างใหม่
ไม่ให้ซื้อแผนที่เต็ม การเผยตำแหน่งทรัพยากร/ศัตรู หรือ pet ที่เปิด Fog ของ Ranked

## 6. การสำรวจและข้อมูลที่ผู้เล่นได้รับ
เริ่มรู้บริเวณฐานตนและ vision รอบยูนิต ปาร์ตี้ผู้ปกป้องแชร์ข้อมูล ฝั่งเอเลี่ยนส่ง worker/scout สำรวจ
หมอกสามสถานะตาม V4: ยังไม่รู้จัก / เคยสำรวจ / กำลังมองเห็น
พื้นที่ที่เคยไปเก็บภูมิประเทศไว้ตลอดแมตช์ ศัตรูเคลื่อนที่เมื่อพ้น vision จะหาย อาคารมี last-seen ghost ตามกติกา
การจำข้อมูลที่สำรวจมาในแมตช์เดียวมีประโยชน์ เพราะใช้ตั้งแนวป้องกันและวางแผน การสุ่มใหม่เกิดตอนเริ่มแมตช์ถัดไป
พื้นที่ที่เคยเปิดแล้วยังต้องส่ง scout กลับไปเพื่อรู้กองทัพ อาคารที่เปลี่ยน หรือแนวซุ่มโจมตีล่าสุด ไม่เห็นสถานะใหม่จากความทรงจำ
สัญญาณแกนเป็นเป้าหมายโดยประมาณที่ประกาศได้ตาม V4 ไม่เปิดอาคาร/ฮีโร่รอบแกนหรือเผยทางลับ
UI ไม่แสดง waypoints ผ่าน terrain ที่ยังไม่รู้จัก ระบบ server คำนวณเส้นทางได้ แต่ client เห็นคำสั่งและข้อมูลเฉพาะที่มีสิทธิ์

สำคัญ: ซ่อน seed อย่างเดียวไม่พอ ถ้าส่งผังเต็ม navmesh ห้องลับและ resource coordinates ไป client ก็สามารถอ่านได้
เซิร์ฟเวอร์เก็บโลกเต็ม ส่ง discovered terrain chunks และ entity snapshots ที่ vision อนุญาต รวม minimap/particles/audio cues ที่เข้ากฎ
ทั้งบอทและ auto-cast รับ observation ที่กรองแล้ว บอทวางแผนจาก frontier/last-seen ไม่ใช้ target หรือแผนที่ศัตรูลับ
spectator/replay ที่รู้ผังเต็มใช้สิทธิ์และ delay; ไม่ให้ replay current match ส่งข้อมูลกลับผู้เล่นขณะกำลังสู้

## 7. PvE, ยศและสิทธิ์ประตู V5
ธีมบท Frost Relay/Ash Garden/Orbital Rain ประกอบใหม่ทุก MissionInstance เป้าหมายและจังหวะเรื่องผูกกับ objective graph ที่ผ่านตรวจ
Guardian Chronicle สุ่มทาง escort, relay, supply rooms และตำแหน่ง encounter; Alien Origins สุ่ม sectors, expansion sites, defender patrols และ outpost routes
ใช้ AccountRank/Ruleset เลือก encounter budget รางวัลฐานตาม mission/difficulty ไม่จ่าย AccountXP จากจำนวน enemy ที่สุ่มออกมาแบบไร้เพดาน
Career Trial สุ่ม placement/sequence ภายใต้โจทย์ทักษะเดียวกัน เพื่อให้สอบวิธีเล่นมากกว่าจำพิกัด
รับประตูแล้วผูก seed/layout กับ instance การ resume/checkpoint/rejoin ใช้สนามเดิมจนจบ ไม่สุ่มใหม่ตอน reconnect
ภารกิจที่ server ยกเลิกก่อนเล่นเพราะ validation ไม่ผ่านไม่ใช้ entry ตาม V5; free practice มี instance/seed คนละชุดกับสนามรางวัลที่ยังไม่เข้า
แบตเตอรี่เพิ่มสิทธิ์ตาม V5 ไม่ซื้อ reroll ฟรีกลาง mission และไม่เพิ่มโอกาสได้เลย์เอาต์ง่าย

## 8. การเปลี่ยนแปลงระหว่างแมตช์
รุ่นแรกผังเดินและพื้นที่ฐานคงเดิมตลอดรอบ ให้ความไม่แน่นอนมาจากสนามใหม่ Fog และการตัดสินใจของคู่ต่อสู้
งานภายหลังอาจเพิ่มพายุ อันตรายตามรอบ หรือประตูเปิดปิดที่มีสัญญาณชัด ตาม event budget และมีเส้นทางสำรอง
ห้ามสร้างกำแพงทับยูนิต ลบฐาน ปิดทุกทางถึง objective หรือเปลี่ยน terrain เพียงเพราะฝ่ายหนึ่งกำลังชนะ
อันตรายรุนแรงต้องมีระยะเตือนตาม gameplay; warning ในบริเวณที่ผู้เล่นมองเห็นกับ global event ประกาศใช้กติกาแยกกัน ไม่ให้ VFX เป็นข้อมูลรั่ว

## 9. ต่อกับงาน 2.5D และเครื่องมือเดิม
สร้าง modular ground/room/bridge/cover/building-footprint ด้วย Blender/Krita/prerender และจัดด้วย Godot TileMapLayer หลายชั้น
TileMapLayer เป็น node ของ Godot สำหรับแผนที่ tile-based และใช้หลาย layer ประกอบกันได้: [เอกสาร Godot](https://docs.godotengine.org/en/stable/classes/class_tilemaplayer.html)
แบ่ง RNG streams เช่น topology/placements/encounters/decoration ไม่ให้เพิ่มเศษตกแต่งแล้วเปลี่ยนทั้งเส้นทางโดยไม่ตั้งใจ
Godot รองรับ seed ที่สร้างลำดับสุ่มซ้ำได้ แต่เอกสารระบุว่าอัลกอริทึมภายในเป็น implementation detail จึงบันทึก layout/result + generator/data version สำหรับ replay ข้ามเวอร์ชันด้วย: [เอกสาร RandomNumberGenerator](https://docs.godotengine.org/en/stable/classes/class_randomnumbergenerator.html)
MapDirector → ZoneGraphBuilder → ModuleAssembler → PlacementPlanner → Connectivity/ClearanceValidator → EconomyEvaluator → NoveltyEvaluator → FogChunkPublisher
nav geometry และ collision ต้องได้จาก layout เดียวกับภาพ ไม่สร้าง terrain สวยแต่ unit เดินทะลุ/ติดขอบ
สร้าง chunk data ล่วงหน้าเท่าที่จำเป็น จัดงานหนักนอก render frame และเริ่ม gameplay หลัง navigation พร้อม
เซิร์ฟเวอร์ตรวจ generator version และเก็บ MatchLayoutBlob, seed, validations และ event log เพื่อแก้ bug โดยไม่เผยของลับก่อนจบ

## 10. สิ่งที่ทำแล้วในตัวอย่างรอบนี้
ไฟล์ corewar-v6-map-generator.js เป็น JavaScript ตัวอย่างที่รันได้ ไม่ใช่ Godot integration:
- สร้างห้องและกราฟทางเดินใหม่จาก seed ต่อ spanning graph และเพิ่มวงรอบ
- เลือกฐานที่อยู่ห่างกันและสร้างพื้นที่เริ่มต้น
- วางทรัพยากรเริ่มต้นฝ่ายละสองจุด ปริมาณเท่ากัน และเดินหกช่องในแบบจำลอง
- สุ่ม relay/cache/hazard ที่เดินถึงได้
- มี LOS, Fog แต่ละฝั่ง, การสำรวจจากทางที่รู้แล้ว และประวัติ fingerprint ล่าสุดในตัวอย่าง
- ตัวอย่างกดสุ่มใหม่/สำรวจ/สลับฝ่าย/ดูผังสำหรับอธิบายได้

ตรวจ candidate 1,000 seeds: ทั้งหมดเชื่อมถึงกัน ทรัพยากรเริ่มต้นเดินถึงตามเงื่อนไข fingerprint ของพื้นไม่ซ้ำในชุดนี้ ฐานห่างอย่างน้อย26ช่อง
ตรวจห้า seeds เดินสำรวจด้วยข้อมูลที่รู้แล้วจนเห็น walkable cells ครบ100%; ตำแหน่งก้าวถัดไปอยู่ในพื้นที่ที่รู้เสมอ
ตรวจ interaction ด้วย DOM harness รวม SVG width320 และตรวจ syntax ผ่าน ยังไม่ได้ตรวจ layout ใน browser
การตรวจนี้ไม่ใช่ผลเกมเพลย์ Godot และไม่ได้พิสูจน์ balance/fps/RTS lane independence ของเกมจริง
ในตัวอย่างทุกอย่างอยู่ใน client เพื่ออธิบาย มีปุ่มดูผังเต็มชัดเจน จึงไม่ใช่โค้ด anti-cheat/server-streaming ที่นำขึ้นออนไลน์ได้ตรง ๆ

## 11. ขั้นต่อไปสำหรับพัฒนาจริง
1. Port กราฟ/placement prototype เข้า graybox Godot ที่มีสองฝั่งในโลกเดียว
2. เพิ่ม unit clearance, zone cut checks, footprint และการประเมินเวลาเดินด้วย unit จริง
3. ทดสอบหลายพัน seeds ต่อ ruleset/faction และ repair/rejection เมื่อไม่ผ่าน
4. ต่อ server-secret layout, Fog chunk streaming, filtered bot observation และ reconnect instance
5. นำหนึ่ง mission Guardian กับหนึ่ง mission MYRAX ของ V5 มาใช้ผังใหม่ พร้อม trial/reward entry ที่ถูกต้อง
6. Blind playtest แล้วค่อยเพิ่ม novelty model, terrain modules, mission families และ event system

เพิ่มระบบนี้ก่อนผลิตแมพตายตัวหลายใบ ชุด art เดิมสามารถประกอบสนามจำนวนมากได้ แต่ยังต้องทำ modules/interfaces/QA ไม่ใช่สุ่ม noise แล้วได้เกมดีทันที
