# HIVE//BREACH — หน้าอัปเกรด สเตตัส สกิล และคริสตัล

> อัปเดต COREWAR 7 ตุลาคม 2026: หน้าอัปเกรดฮีโร่นี้ใช้จัดชุดก่อนแมตช์ โหมดแข่งขันใช้คลังคริสตัลมาตรฐานที่ทุกคนเข้าถึงและงบพลัง 10 แต้มเท่ากัน ไม่ใช้ความก้าวหน้าถาวรสร้างความได้เปรียบ ฝั่งเอเลี่ยนวิจัยระหว่างแมตช์ด้วยทรัพยากร/เวลาและเกมไม่หยุดเมื่อเปิด UI รายละเอียดล่าสุดอยู่ใน [COREWAR-V2-DESIGN.th.md](COREWAR-V2-DESIGN.th.md)

วันที่ 7 ตุลาคม 2026 · ข้อเสนอ UI และระบบที่ต่อจากลีรา/เวลเว็ต · ภาพคอนเซปต์ ไม่ใช่ระบบเกมที่สร้างแล้ว

## รูปแบบหน้า

ธีมโกธิคไซไฟ: แผงดำโปร่ง ขอบโลหะเงิน เส้นพลัง magenta และข้อความสถานะ cyan คริสตัลมีรูปทรงชัดเจนแตกต่างกัน ไม่ใช้สีเพียงอย่างเดียว โมเดลตัวละครและอุปกรณ์อยู่บนแท่นพรีวิวในฐานพัก

แถบหลัก LOADOUT / SKILLS / CRYSTALS ใช้ตัวละครที่เลือกอยู่ร่วมกัน หน้าแรกของภาพนี้ใช้ VELVET และ Requiem Hammer เพื่อให้เห็นช่องใส่ gem บนอาวุธใหญ่ ระบบเดียวกันใช้กับเกราะและปืนพกของลีราได้

## ภาพ 1 — Crystal Forge

ไฟล์ `velvet-crystal-forge-ui-v1.png`

- ซ้าย: ตัวละคร เลเวล ชื่อสายเล่น และสเตตัส HP/ป้องกัน/พลังโจมตี/ฮีลเมื่อฆ่า/ความเร็วเดิน
- กลาง: พรีวิวตัวละครเต็มตัวพร้อมอาวุธ เส้นเชื่อมแสดงชิ้นอุปกรณ์ที่เลือก และ gem บนโมเดลสว่างตามชนิดคริสตัล
- ขวา: การ์ดอาวุธและเกราะ พร้อม socket, กระเป๋าคริสตัล และรายละเอียด gem ที่เลือก
- ล่าง: ปุ่มยืนยัน INSTALL CRYSTAL และ CANCEL อยู่ตำแหน่งเดิมทุกครั้ง

สถานะภาพคือกำลังพรีวิวติดตั้ง Ruby III ในช่องว่างของค้อน ค่าโจมตี 420→510 ยังไม่ถือว่าติดตั้งสำเร็จ สเตตัสเกราะไม่เปลี่ยนจากการใส่ gem อาวุธครั้งนี้ ตัวเลขเป็นตัวอย่างสำหรับออกแบบ

## ภาพ 2 — Skill Ascension

ไฟล์ `velvet-skill-ascension-ui-v1.png`

ผังสามสาย IRON GUARD (ถึก/ป้องกัน), HAMMER COMBO (โจมตี/คอมโบ), BLOOD SIPHON (ดูดเลือดเมื่อฆ่า) แสดงโหนดที่มีแล้ว ปลดล็อกได้ และยังล็อกด้วย icon/ขอบ/ป้าย rank ไม่อาศัยสีอย่างเดียว

เมื่อเลือกโหนด แผงขวาแสดงระดับปัจจุบัน→ระดับใหม่ ผลสกิลที่เพิ่ม แต้มที่ใช้ และแต้มหลังซื้อ ภาพตัวอย่าง Blood Siphon ระดับ3/5→4/5 ฮีลเมื่อฆ่า4%→5%, 60→75 HP เมื่อ maxHP1500 และ BloodPower8→10 มี4แต้มใช้1เหลือ3 ตัวเลขยังเป็นข้อเสนอ ไม่ใช่ค่าที่ทดสอบแล้ว

คอมโบสามท่าแสดงเป็น SWEEP→LIFT→SLAM เพื่อเชื่อมกับสิ่งที่ผู้เล่นใช้จริง ผังสกิลอยู่คนละแท็บกับ socket เพื่อให้ผู้เล่นรู้ชัดว่ากำลังใช้แต้มกับสกิลหรือเปลี่ยนอุปกรณ์

ผังนี้เสนอให้เป็นความก้าวหน้าถาวรของตัวละครในฐาน ได้แต้มจากเลเวลตัวละครที่บันทึกหลังภารกิจ ส่วนการเลือก1ใน3การ์ดระหว่างรอบตามแผนเดิมเป็นบัฟชั่วคราวของรอบนั้น ไม่เพิ่มrankในผังอย่างเงียบๆ สเตตัสในฐานแสดงคลาส+สกิลถาวร+อุปกรณ์; ระหว่างภารกิจมีแผงสถานะแยกบัฟชั่วคราวให้เห็น

## ระบบคริสตัลที่เสนอ

คริสตัลได้จากภารกิจ รัง ศัตรูพิเศษ และบอส เริ่มเดโมด้วยการดรอปที่กำหนดไว้และรางวัลแน่นอนสำหรับภารกิจแรก ไม่ต้องเริ่มจากระบบสุ่มซับซ้อน

| คริสตัล | สี/รูปทรง | ใส่กับ | ผลตัวอย่าง |
|---|---|---|---|
| Ruby | แดง / เพชร | อาวุธ | พลังโจมตี +30/+60/+90 ตาม Tier I/II/III |
| Sapphire | ฟ้า / โล่ | เกราะ | เพิ่มการลดดาเมจที่เกราะรองรับ +2/+3/+5 จุดเปอร์เซ็นต์ |
| Emerald | เขียว / ใบไม้ | เกราะ | HP สูงสุด +50/+100/+150 |
| Amethyst | ม่วง / หยด | อาวุธ | เพิ่มแรง stagger +4/+7/+10% |

ตัวเลขทั้งหมดเป็นค่าตั้งต้นตามตัวอย่าง UI ไม่ใช่เจ้าของยืนยันหรือผลบาลานซ์จริง ตัวอย่าง Sapphire ทำให้35%→40% คือเพิ่ม5จุดเปอร์เซ็นต์ ไม่ใช่คูณ35%ด้วย1.05

ข้อเสนอเริ่มต้น: อาวุธมี3ช่อง เกราะมี2ช่อง ใช้ได้ไม่เกินจำนวนช่อง ช่องที่ล็อกยังไม่มีในเดโมแรกเพื่อลดระบบปลดล็อกอุปกรณ์เกินจำเป็น ชนิดคริสตัลบอกทั้งไอคอนอุปกรณ์และข้อความ WEAPON/ARMOR เมื่อไม่ตรงช่องปุ่มยืนยันจะกดไม่ได้ พร้อมบอกเหตุผล

คริสตัลทั่วไปซ้ำประเภทได้ตามจำนวนช่อง แต่ผลรวมมีเพดานที่กำหนดในข้อมูล: ป้องกันจากเกราะสูงสุด60%เป็นเพดานทดลอง, โบนัส stagger จากgemไม่เกิน30% เอฟเฟกต์ชนิดพิเศษในอนาคตควรใช้กลุ่ม unique เพื่อไม่ซ้อนพฤติกรรมซ้ำ เดโมไม่ต้องมีคริสตัลหายากที่เปลี่ยนระบบสกิลหลายอย่างพร้อมกัน

เพิ่ม3คริสตัลTierเดียวกันประเภทเดียวกันเป็นTierถัดไปได้หลังเดโม หากทำระบบรวม ให้แสดงรายการ3ก้อนที่จะใช้และผลลัพธ์ก่อนยืนยัน ไม่มีโอกาสล้มเหลวในข้อเสนอนี้ และไม่จำเป็นต้องเพิ่มระบบรวมให้เดโมแรก

## การใส่และถอด

1. เลือกชิ้นอุปกรณ์ → ช่องที่ต้องการ → คริสตัลจากกระเป๋า หรือใช้ลากวางเป็นทางเลือก
2. ระบบตรวจชนิด socket และจำนวนคริสตัลในกระเป๋า
3. แสดงค่า before/after ของสเตตัสที่กระทบ, gem ที่จะใส่ และ gem เก่าที่จะคืนกระเป๋าหากเป็นการแทนที่
4. กดยืนยันจึงย้ายรายการและบันทึก; CANCEL คืนพรีวิวเป็นข้อมูลจริง
5. ถอดฟรี คริสตัลคืนกระเป๋า ไม่ทำลาย gem การเปลี่ยนทำในฐาน/จุดพัก ไม่สลับกลางคอมโบ

ต้องมีการเลือกด้วยคลิก/คีย์บอร์ด/จอยที่ทำงานเท่ากับการลาก เพราะการลากอย่างเดียวใช้งานยากกับจอยและคนที่ควบคุมเมาส์ไม่ถนัด Tooltip ไม่เป็นที่เดียวที่บอกผลสำคัญ แผงรายละเอียดแสดงข้อมูลทั้งหมดที่จำเป็นสำหรับตัดสินใจ

อัปสกิลใช้แต้มสกิล ส่วน socket ย้ายอุปกรณ์ ไม่หักแต้มสกิล ทั้งสองแสดงต้นทุนตามจริงและมีปุ่มยืนยันของตัวเอง

## การคำนวณและการบันทึก

สเตตัสควรคำนวณใหม่จาก base ของคลาส + การเพิ่มแบบค่าคงที่ + modifierเปอร์เซ็นต์ + ผลสกิล โดยกำหนดลำดับแน่นอนและคำนวณจากต้นทางทุกครั้ง ไม่บวกโบนัสทับสเตตัสเดิมตอนเปิด/ปิดเมนู

- CrystalDefinition: id, type, tier, compatibleEquipment, modifiers, icon, socketVisual
- EquipmentInstance: instanceId, definitionId, socketCount, socketCrystalInstanceIds
- CrystalInstance: instanceId, definitionId และตำแหน่ง owner inventory/equipment
- SkillProgress: skillId, rank และแต้มที่เหลือ
- PreviewBuild: สำเนาข้อมูลสำหรับคำนวณก่อนยืนยัน ไม่แก้ save ตัวจริง

ต้องย้ายgemแบบครั้งเดียวในการยืนยัน ไม่ให้ก้อนเดียวมีทั้งในกระเป๋าและอุปกรณ์ หากsaveล้มเหลวคืนข้อมูลก่อนทำรายการ มี save version และตรวจ ID จำนวนช่อง rank/แต้มและผลเพดานหลังโหลด

เทียบค่าพรีวิวกับค่าหลังยืนยันด้วยสูตรเดียวกัน เช่น Ruby+90 ทำให้420→510, Sapphire+5จุดทำให้35%→40%, BloodSiphon5%*1500=75 HP ต่อkillก่อนเพดานฮีล ถอดgemกลับค่าฐานเดิมและไม่คืนแต้มสกิลที่ใช้แล้วโดยผิดพลาด

## ทำภาพนี้เป็นหน้าเกมจริง

Godot Control containers สำหรับ layout, รายการสเตตัสและ item grid เป็น component ที่ใช้ซ้ำได้, แยกข้อมูลจาก UI. ตัวละครพรีวิวใช้spriteที่renderไว้หรือSubViewport3Dเมื่อมีโมเดลจริง การเรืองแสงอยู่ในชั้นpreviewไม่ทับข้อความ

เดโมเริ่ม4ชนิดคริสตัล ×3Tier, 2ชิ้นอุปกรณ์ต่อคลาส, SkillTreeเวลเว็ต3สายรวมประมาณ9–12โหนด และแบบทดสอบ3กรณีสำคัญ: ใส่ผิดประเภทไม่ผ่าน; ใส่/แทนที่/ถอดไม่เพิ่มgemซ้ำ; สเตตัสพรีวิวเท่าค่าหลังยืนยัน/โหลดsave

ยังไม่ได้เขียนระบบเกม UI นี้ ภาพที่ได้จาก image_gen ใช้เป็นเป้าหมายสี โครงหน้า และการจัดลำดับข้อมูล ข้อความจริงและค่าอัปเกรดต้องวาดจากข้อมูลใน UI ไม่ใช้ภาพคอนเซปต์เป็นเมนูที่คลิกได้โดยตรง

ตรวจภาพทั้งสองแล้ว: หน้าคริสตัลเห็น5socket แยก3weapon/2armor, คลัง8ช่อง, ค่าโจมตี420→510 และปุ่มINSTALL; หน้าสกิลเห็น3สาย, selectedBloodSiphon3/5→4/5, HPต่อkill60→75 และแต้ม4ใช้1เหลือ3 มีข้อความย่อยเหนือป้ายIRON VEILที่คลาดเคลื่อนในภาพAI ต้องเอาออกหรือวาดใหม่จากข้อมูลเมื่อทำUIจริง ป้ายหลัก/ตัวเลขก่อนหลังอ่านได้ ภาพถือเป็นคอนเซปต์ ไม่ใช่textureข้อความสำหรับส่งเกม
